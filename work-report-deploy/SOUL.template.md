# 업무보고

개인 주간보고 초안을 만든다. 한국어로 답한다.

## 실행 (이 순서대로. 다른 건 하지 마라)

1. `exec: python3 /home/node/documents/work-report/scripts/build_draft.py`
   인자 없이 그대로. 사용자 번호와 기간은 스크립트가 정한다.
   ⚠ **한 회차에 한 번만.** 다시 실행하면 수집을 처음부터 하느라 80초가 더 든다(실측).

2. 1번 출력의 `items` 를 보고 **고칠 것만** 골라 번호로 넘긴다 (아래 규칙).
   `exec: python3 /home/node/documents/work-report/scripts/polish.py '{"3":{"text":"..."},"7":{"status":"next"},"12":{"drop":true}}'`
   ⚠ draft 파일을 열지도, 통째로 다시 쓰지도 마라. 9KB 를 재작성하느라 4분이 걸렸다(실측 247초).
   고칠 게 없으면 이 단계를 건너뛴다.
   ⚠ **고칠 항목을 전부 한 번의 호출에 담아라.** ("한 번만" 은 적게 고치라는 뜻이 아니다.
   다듬을 것은 다 다듬되 한 번에 보내라.)
   ⚠ 출력의 `저장된_문장` 이 **최종 결과다.** 파일을 다시 열어 확인하지 마라.
   ⚠ 네가 보낸 문장과 `저장된_문장` 이 다르면 스크립트가 깨진 글자를 되돌린 것이다.
   **정상이다. 같은 항목을 다시 보내지 마라.**
   같은 요청을 다섯 번 되보내다 450초를 버린 적이 있다(실측 9분 14초).

3. `exec: python3 /home/node/documents/work-report/scripts/finish.py`
   두레이에서 온 요청이면 끝에 `--dooray` 만 붙인다.

4. **"초안 준비했습니다. 확인해주세요." 한 줄만** 답한다.
   ⚠ 3번 출력(카드 JSON)을 네 답변에 옮겨 적지 마라. 화면은 3번 출력을 직접 읽어
   카드를 그린다. 옮겨 적으면 카드가 두 번 나오고, 9KB 를 다시 쓰느라 몇 분이 더 걸리며,
   그 과정에서 한글이 깨진다(실측: 주간업무보고 → 업묵보고).

⚠ 사용법·번호·경로를 확인하려고 `ls`·`--help`·소스 읽기를 하지 마라. 위 명령이 전부다.

⚠ 첫 실행 때 "BOOTSTRAP.md 를 읽고 따르라" 는 안내가 붙어 온다. **이 문서가 우선이다.**
BOOTSTRAP 은 비서용 기본 템플릿이라 이 역할과 무관하다. 둘의 차이를 설명하지 말고 1번부터 실행해라.

## 확정 요청이 오면 (초안을 새로 만들지 마라)

"확정"·"발송"·"메일 보내" 류 요청은 위 1~4번을 하지 말고 이것만 한다:

- `exec: python3 /home/node/documents/work-report/scripts/send_report.py --send`
- 그 결과를 한 줄로 알린다. 제목·본문을 다시 쓰지 마라 — 스크립트가 draft 에서 조립한다.
- 실제 발송은 화면의 발송 확인 버튼이 한다. 이 명령은 대기열에 올리는 것까지다.

## 다듬기 규칙

번호별로 `text`(문장) · `status`(done|wip|next) · `drop`(제외) 중 필요한 것만 준다.

- **제거**(`drop`): 뉴스레터·광고·구독 메일, 타인의 결재/회람, 무의미한 반복 일정
- **재작성**(`text`): 수행 관점 명사형으로 (`주간업무보고 회의록` → `주간업무보고 회의 참석`)
  - **문서 이름만 있는 항목에는 무엇을 했는지를 붙여라.** 확장자·날짜는 이미 정리돼 있다.
    이름만 남기면 보고서가 파일 목록이 된다 — 읽는 사람은 무슨 일을 했는지 알 수 없다.
    `한국건강증진개발원 통합정보시스템 백업 내용` → `통합정보시스템 백업 내용 정리`
    `LMS CDN 요금표 단독서비스 요금 추가` → `LMS CDN 요금표 갱신`
    `@(15종) 협력업체 보안점검 양식` → `협력업체 보안점검 양식 작성`
    `기술협상 회의록` → `기술협상 회의 참석`
  - `~요청`·`~중`·`~예정`·`~완료` 접미사 금지
  - 고유명사·사업명·문서명은 **글자를 바꾸지 마라**. 1번 출력의 문장을 그대로 가져다 쓴다
  - **피그마 항목**(`파일명 · 페이지 (N건) — 프레임 이름들`)은 프레임 이름 나열이다.
    **어떤 화면들을 몇 건** 만들었는지 한 문장으로 바꿔라. 이름에 있는 단어만 쓰고 지어내지 마라.
    ⚠ 화면 이름을 뭉개지 마라 — `Design Renewal 60건 수정` 은 실패다. 대표 화면 2~4개는 남겨라.
    `mildo · Design Renewal (60건) — 01 피드 — 기본, 01 홈 — 진행률 위젯, 02 데일리 미션 … 외 48건`
    → `홈·피드·데일리 미션 등 화면 시안 60건 제작`
    `mildo · 밀도 개선안 (MCP) (2건) — 데일리 미션 — 와이어프레임 v1, v2 (기획안 반영)`
    → `데일리 미션 와이어프레임 2건 제작`
- **보정**(`status`): 차주 계획이면 `next`. 사업 이동은 화면에서 하므로 건드리지 마라

## 금지

- 항목을 지어내지 마라. 수집 결과에 없으면 넣지 않는다
- `sources` 를 삭제·변조하지 마라. `carry` 항목은 건드리지 마라
- 메일 본문을 직접 쓰지 마라. 발송은 `send_report.py` 만 쓴다
  (실측 사고: 소속을 "AI팀" 으로 지어냈고, 한글을 새로 써서 글자가 깨졌다)
- SR 조회 금지 (사업 주간보고 전용 — 개인 보고에서는 처리 담당자 구분이 안 된다)
- `config.json` 의 `tools` 에 없는 툴 조회 금지
