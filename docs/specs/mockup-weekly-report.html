카드는 전부 비서가 띄운다 sessions_spawn 결과는 자동으로 비서에게 반환된다 (Results auto-announce to your requester). 사용자가 "전달" 같은 걸 누를 필요가 없다. 업무보고 에이전트는 데이터를 만들어 넘기기만 하고, 화면에 그리는 건 비서 몫이다.
사업 주간보고와 다른 점 business-report는 사용자가 그 에이전트 화면에 직접 들어가서 대화한다 (biz-picker·draft-card를 자기가 띄움). 업무보고는 반대로 비서 화면 안에서만 동작한다 — 요구사항 5를 지키려면 이 방식이어야 한다. 대신 비서 쪽에 "서브에이전트 결과를 카드로 재발행" 규칙이 필요하다.

1담당 업무 등록 설정 화면

외부 연동 › 담당 업무. 한 번 등록해 두면 cron이 이 설정으로 자동 실행된다.

주기와 툴은 사람 단위 · 사업은 분류용 주간보고는 한 사람이 주 1회 쓴다. 사업별로 주기를 두면 사업 3개인 사람은 보고를 3번 받게 된다. 툴도 마찬가지 — 사업마다 다르게 두면 설정이 사업 수만큼 늘어난다. 담당 사업은 보고 항목을 [사업명]으로 묶는 분류 키로만 쓴다.

🔗 증적 링크 — 출처별 생성 가능 여부 (2026-08-06 실측)

출처가능링크 형태 · 근거
구글 드라이브가능 docs.google.com/document/d/{id}
`gog drive`가 파일 id 반환 · 8/5 사업보고에서 이미 이 방식으로 증적 링크를 넣은 이력 있음
Gmail가능 mail.google.com/mail/u/0/#all/{id}
`gog mail search`가 id·threadId 반환
SR 시스템미사용 링크 생성은 가능하나 개인 업무보고에서는 제외
처리 담당자 구분 불가 → 사업 주간보고 🏢 전용
두레이가능 {두레이도메인}/task/{projectId}/{taskId}
사업 meta.json에 dooray_project_id 이미 보관 · 도메인만 설정에 추가하면 됨
구글 캘린더보완 필요 `gog calendar`가 이벤트 id는 주지만 htmlLink는 반환하지 않음. id→URL 변환에 base64 인코딩이 필요해 불안정 → gog에 htmlLink 필드 추가 권장
GitHub가능 github.com/{owner}/{repo}/pull/{n} · 연동 설정에 owner·repo 이미 있음
Figma개발 시 포함 figma.com/file/{key} · 연동 자체가 신규
링크는 초안 데이터에 같이 저장한다 항목마다 { text, source, url } 형태로 들고 있다가, 화면에서는 출처를 클릭 가능하게 하고 메일 본문에는 링크를 함께 넣는다 (받는 사람도 증적을 바로 확인 가능).
링크가 없는 항목도 있다 사용자가 직접 추가한 항목이나 캘린더처럼 링크를 못 만드는 출처는 — 로 비워 둔다. 억지로 만들어 붙이면 깨진 링크가 보고서에 남는다.
화면은 사업별, 메일은 기존 양식 보는 사람(본인)은 사업별로 묶여야 빠진 게 보이고, 받는 사람(대표)은 기존 메일 양식이 익숙하다. 둘을 분리한다. 「메일 형태로 보기」로 발송될 본문을 그대로 확인할 수 있다.
활동 없는 사업도 접어서 표시 이번 주 항목이 없으면 「활동 없음」으로 흐리게 남긴다. 아예 빼면 빠뜨린 건지 없는 건지 구분이 안 된다.

⑧ 메일 수신자가 설정에 없다

지금은 비서 BOOTSTRAP.md에 직원 목록(이름→이메일)만 하드코딩돼 있다. 주간보고를 누구에게 보내는지는 어디에도 없어서, 매번 사용자가 말해야 한다.
→ 개인 설정에 기본 수신자 · 참조를 두고 비서가 참조한다. 사람마다 보고 받는 상급자가 다를 수 있어 전체 공용으로 두지 않는다.

⑪ 이름만 바꿔서는 혼선이 안 풀린다 실측 확인

sync-agents.sh가 만드는 비서의 위임 규칙표가 이 상태다.
## 위임 규칙
| 키워드 | 호출할 팀원 |
| reporter         | reporter         | ← 키워드 = 에이전트 ID
| business-report | business-report |
keyword_map에는 developer·reviewer·planner 등 7개 기본 역할만 정의돼 있다. reporter·business-report는 없어서 ID가 그대로 키워드가 된다. 즉 "주간보고 작성해줘"에 대한 규칙이 아예 없고, 순전히 LLM이 이름 보고 판단한다.
순서필요한 조치

work-report → "업무보고, 내 업무, 이번 주 한 일, 메일 주간보고"

⑩ 초안이 유실될 수 있다

OpenClaw는 모델 응답이 성공해야 세션에 기록한다. 8/3~8/4에 크레딧이 소진되자 사용자 발화까지 통째로 사라졌다. 목요일 cron이 초안을 만들었어도 같은 일이 생기면 금요일에 아무것도 남지 않는다.
→ 초안은 세션이 아니라 파일로 저장하고(사업 주간보고의 draft.json처럼), 화면은 그 파일을 읽어 그린다. 대화가 날아가도 초안은 남는다.
