## 0. 목표 맥락

올해 목표는 구성원 1인당 AI 팀원 4~5명 체계 구축.

실측(2026-08-12): 에이전트 105개 중 **63%가 세션 0건**. 문제는 머릿수가 아니라
**일이 흘러들어갈 계기(정기·이벤트·진입점)의 부재**다. 이 설계는 "만들기"가 아니라
"일이 흘러가게 하기"에 초점을 둔다.

## 2. 아키텍처 원칙

### 2.1 서브에이전트 = 데이터 생성기
- 카드(fenced code block)를 뱉지 않는다. 메일을 보내지 않는다.
- 산출물은 **파일**(`draft.json`)이며, 반환은 경로+요약 한 줄.
- 비서가 파일을 읽어 카드로 재발행하고, 수정을 반영하고, 발송까지 담당한다.
- `business-report` 는 `[Subagent Context]` 유무로 분기: 비서 경유면 JSON 반환,
  직접 진입이면 기존대로 카드 발행 (하위호환).

### 2.2 비서 직접 처리 vs 위임 — 기준은 "결과물"
- 답이 **대화 몇 줄**(브리핑·SR 요약·일정·미답 메일) → **비서가 직접** 도구 실행 (빠름)
- **파일·메일·편집 카드**가 만들어져야 함 → **서브에이전트 위임**

### 2.3 사용자는 에이전트를 고르지 않는다
- 진입: **업무 칩**(빠른 실행 버튼 = 업무 바로가기, 에이전트 선택기 아님) + **자연어**
- 위임 판단: `sync-agents.sh` 의 `keyword_map` — **발화 기준 키워드**로 확장
  - `work-report`: 업무보고, 내 업무, 이번 주 한 일, 주간 업무, 메일 주간보고
  - `business-report`: 사업 주간보고, 사업보고, 기관 보고, SR, HWPX, 한글 보고서
  - **기존 커스텀 에이전트도 등록** (docwriter·designer 등 — 위임 0건 7명에게 통로 제공)
- 애매하면 **한 번만** 되묻되, 에이전트 이름이 아니라 **결과물**로 묻는다:
  "① 대표님께 보내는 메일 주간보고 ② 발주기관에 제출하는 한글 보고서"
- 기존 @멘션 칩은 파워유저 지름길로 존치.

### 2.4 초안은 세션이 아니라 파일에 산다
- OpenClaw 는 모델 응답 성공 시에만 세션 기록 → API 장애 시 대화 소실 (8/3~8/4 실증)
- `draft.json` 을 **주차별로 보관**: `work-report/drafts/draft-2026-W33.json`
- 화면은 파일을 읽어 그린다. 세션이 날아가도 초안은 남는다.

## 3. 설정 모델

### 3.1 사업 마스터 (공용 · 관리자 관리)
- `/opt/openclaw/data/businesses.json` — 사업당 1개: `{id, name, org, dooray_project_id, figma_file_keys, members[]}`
- **관리자가 등록하고 담당자(members)까지 지정**한다. 개인은 등록하지 않는다.
- 근거: 같은 사업이 사람마다 다른 ID (user02 `e-jinro-support` ↔ user13 `2026-sports` 실측)
- 담당 사업은 보고 항목의 **분류 키** — 항목 앞 `[사업명]` 태그.
- 기존 「공공사업 시스템」 등록분을 마스터로 승격.

### 3.2 개인 설정 (`data/userNN/work-report/config.json`)
```json
{
  "tools": ["dooray", "gmail", "calendar"],
  "dooray_member_id": "",
  "github": { "owner": "", "repo": "" },
  "profile": { "team": "", "name": "", "title": "" },
  "recipients": { "to": [], "cc": [] },
  "schedule": { "enabled": true, "expr": "0 17 * * 4", "tz": "Asia/Seoul" }
}
```
- **툴 = 사람당 1벌** (사업별 아님). **주기 = 사람당 1개.**
- 미연동 툴은 UI 에서 비활성(「연동 필요」) — 선택 자체가 불가.
- 기본값 수정은 설정 화면에서만. 대화·카드 조정은 **해당 회차 1회** 한정.
  카드의 「이 구성을 기본값으로 저장」 체크로만 승격.
- 최초 1회 설정: 관리자(사업+담당), 본인(툴·수신자 **확인만** — 기본값 선채움).

## 4. 수집 · 초안 생성

### 4.1 수집 (SR 제외)
| 툴 | 본인 필터 | 비고 |
|---|---|---|
| 두레이 | `memberIds` 파라미터 | 사업 마스터의 `dooray_project_id` 대상 |
| Gmail / 캘린더 / 드라이브 | 본인 계정 | 자동 |
| GitHub | 본인 커밋·PR | 연동 UI 기존재 · 미사용 상태 |
| Figma | 파일 버전 이력에서 본인 것 | **연동 신규 개발** · 마스터의 `figma_file_keys` 대상 |
| ~~SR~~ | **불가** | 목록에 처리 담당자 컬럼 없음 (`requester` 는 발주처) → **영구 제외**, 기관 보고 전용 |

- 미연동 툴 호출 금지 (호출 시 에러가 아니라 사용법 안내문이 와서 **조용한 누락** 발생 — 실측)
- 툴별 수집 건수(stats)를 남겨 **부분 실패를 드러낸다**.

### 4.2 가공
- **중복 병합**: 제목 유사도 + 시각 근접(3일)으로 묶고 출처를 한 항목에 복수 표기
  (한 작업이 두레이·메일·드라이브에 3줄로 부풀던 문제)
- **노이즈 압축**: 사소 항목(문구·오탈자 등) 3건 이상이면 "…등 N건" 한 줄로
- **이월 대조** ✅채택: 직전 주차 draft 의 「차주」를 이번 회차와 대조 —
  이어지면 「지난주 예정 → 계속」 표시, 완료됐으면 완료로. 보고를 관리 루프로 만든다.
- **출처 없는 항목 경고**: 직접 입력(정상) / 링크 불가 출처(정상) / 출처 전무(⚠ 환각 의심) 구분

### 4.3 draft.json
```
{ period, generated_at, businesses:[{id,name,items:[{text,status,sources:[{source,url}],carry?}]}],
  common:[...], stats:{dooray:12,...}, warnings:[...] }
```
- 활동 없는 사업도 빈 배열로 남긴다 (빠뜨림/없음 구분).

## 5. 화면 (전부 비서가 발행)

### 5.1 초안 카드 — 「보고서 미리보기형」 (`\`\`\`work-draft`)
- 상단: 기간 + 생성 시각 + **요약 숫자** (완료 n · 진행중 n · 차주 n)
- 본문: **메일과 동일 구조** — `■ 완료 / ■ 진행 · 차주 계획 / ■ 업무 - AI 툴 활용`
  - 항목 앞 `[사업명]` 태그 (공통 항목은 태그 없음)
  - 우측 출처 링크 (`두레이 #163 ↗`), 이월 표시, 묶음 표시
- **화면에서 본 것 = 발송되는 것.** 「메일 형태로 보기」 버튼 불필요.
- 색: **청록 단색** — 숫자·■제목·태그·링크 모두 같은 계열, 굵기·투명도로만 위계.
- 부분 실패 시 카드 상단 배지: 「⚠ Gmail 수집 실패 — 재연동」 ✅채택
- 항목 클릭 → 채팅창 수정 프리필. 버튼: 초기화 / ✓ 확정.

### 5.2 툴 조정 카드 (`\`\`\`tool-pick`) — 기본은 안 뜸
- "조회할 곳 바꿔줘" 요청 시에만. 기본값 선체크 · 해당 회차만 적용.

### 5.3 발송 확인 카드
- 제목·수신자(개인 설정 선채움)·참조 표시 → 명시적 승인 후 발송.

## 6. 메일

- 제목: `[주간보고][YYYY-MM-DD~YYYY-MM-DD]팀이름 이름 직책` — **`(AI)` 등 표기 금지**
  (실측: `(AI)` 붙은 cron 발송과 사람 발송이 같은 주 2통씩 나가던 문제)
- 본문: 기존 텍스트 양식 유지 (표 금지). `[사업명]` 접두어, 증적 URL 은 `↳ 증적:` 하위 줄.
- 발송 주체는 **비서만**. **주 1회** — 이미 발송했으면 재발송 전 반드시 확인.
- 발송 후 정정: 자동화하지 않음. `[재발송]` 제목으로 수동만.

## 7. 자동 실행 (cron)

- `0 17 * * 4` · **tz Asia/Seoul 고정** (실측: 기존 발송 시각이 -0700/-0500/-0400 혼재)
- 지시문은 한 줄 ("이번 주 업무보고 초안을 생성하라") — 툴·사용자 정보는 설정에서.
  기존처럼 1,400자 프롬프트에 도구·이메일 하드코딩 금지.
- **초안까지만.** 발송은 사람 승인.
- **공휴일·연차 분기** ✅채택: 금요일이 휴무면 목요일 알림에 "내일 휴무 — 오늘 발송할까요?" 제안
  (기존 user13 cron 로직 승계)
- 실행 이력 `runs.json`: 시각·성공여부·툴별 수집 건수·오류. 실패는 다음 접속 시 비서가 먼저 알림.

## 8. 두레이 연동 (Phase 2 — 코어 완료 후)

- **B안 채택**: 지시 받기 + 회신/알림. **C안(이벤트 트리거) 보류.**
- 형태: 대화방 목록에 **「TideClaw 비서」 전용 방 1인 1개** (나와의 대화방 아님).
  방 안에서는 **@ 불필요** — 그냥 말한다.
- 세션: webhooks 확장의 `sessionKey` 를 **웹의 비서 세션과 동일하게** — 두레이에서 한 말이
  웹 대화창에 남고 이어진다 (비서는 한 명, 문이 두 개).
- 흐름: 두레이 Outgoing → OpenClaw `webhooks`(path·secret) → 비서 세션 → Incoming 회신
- 알림(수신 방향): 아침 브리핑 · 목 17시 초안 준비 · **생성 실패** · (휴무 분기 질문)
- 한계 명시: 메신저에 카드 UI 없음 → 짧은 질의·알림까지만, 편집·확정은 "웹에서 열기" 링크로.
- 착수 시 확인: 두레이 **메신저 봇 API**(1:1, 이상적) vs **웹훅+트리거 단어**(`/비서 …`) 중
  지원되는 쪽 · 두레이 계정 ↔ userNN 매핑 테이블.
