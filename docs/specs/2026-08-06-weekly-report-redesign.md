# 주간보고 개편 설계 (구버전 — 2026-08-12-work-report-design.md 로 대체됨)

> 상태: **설계 중** · 다음 단계: HTML 목업으로 UI 흐름 확정

## 1. 배경

"주간보고"라는 말이 **두 가지 서로 다른 산출물**을 가리켜 LLM이 계속 혼동한다.
이 문제로 이미 `사업 주간보고`를 비서 밖으로 분리한 이력이 있으나, **개인 주간보고가 여전히 비서 안에 남아 있어** 근본 해결이 안 된 상태다.

| | 개인 주간보고 | 사업 주간보고 |
|---|---|---|
| 내용 | 내가 이번 주 한 일 | 담당 사업의 SR 처리 내역 |
| 산출물 | **메일 본문** | **HWPX 파일** |
| 현재 위치 | 비서 `BOOTSTRAP.md` 103~127행 | `business-report` 에이전트 (분리 완료) |
| 주기 | 금요일 메일 발송 | 주 단위 |

## 2. 현황 조사 결과 (2026-08-06)

### 2.1 개인 주간보고는 비서에 박혀 있다

- **양식**: `data/userNN/BOOTSTRAP.md` 103~127행 — 메일 발송 섹션 안에 제목/본문 양식이 하드코딩
- **배포**: 배포 스크립트 없음 · 수동 관리 · 15개 컨테이너 동일(md5 일치) · **user16에는 파일 자체가 없음**
- **참고**: `shared/userNN/SOUL.md`·`AGENTS.md`는 `scripts/sync-agents.sh`가 자동 생성 (수동 수정 시 덮어씀)

### 2.2 cron이 전부 비서를 직접 호출한다

서브에이전트가 있어도 cron은 `secretary`를 부른다. 비서가 오케스트레이터가 아니라 **실무자**로 쓰이는 상태.

| 사용자 | 스케줄 | 호출 대상 | 이름 |
|---|---|---|---|
| user05 | `0 17 * * 4` | secretary | 주간보고 초안 작성 (목 17시) |
| user05 | `0 18 * * 3` | secretary | 주간보고 초안 작성 (수 18시, 금 연차) |
| user05 | `0 10 * * 5` | secretary | 주간보고 내용 업데이트 (금 10시) |
| user13 | `0 15 * * 4,5` | secretary | 주간보고 자동 작성 (목·금 15시) |
| user09 | `at` (off) | secretary | 주간보고 메일 발송 |

그 외 morning-brief(user01·11·12·14), bid 공고체크(user13), 일일 동향 보고(user07) 등이 있음.

### 2.3 개인 보고 에이전트 이름이 제각각이다

| 사용자 | 에이전트 ID |
|---|---|
| user02, user03 | `reporter` (표시명 "주간보고 작성 📊") |
| user07 | `weekly-report-agent` |

`reporter`는 workspace/agentDir가 분리돼 있지 않아 **비서와 같은 SOUL.md·BOOTSTRAP.md를 읽는다**.
반면 `business-report`는 `workspace-business-report` + 전용 agentDir로 완전히 분리돼 있다.

### 2.4 도구 연동 현황

**extension은 16명 전원 동일하게 설치돼 있다.**

```
bid · dooray · drive-advanced · file-share · g2b · gmail · hwp · local-files · rag
```

**외부 연동(토큰 등록) 현황은 다르다.**

| 도구 | 등록 UI | 실제 연동 | 비고 |
|---|---|---|---|
| Dooray | 있음 | user05·07·13·15 확인 | `integrations.json` |
| GitHub | **있음** (Owner/Token/Repo) | **0명** | 미사용 상태 |
| 공공사업 시스템(SR) | 있음 | business-report 사용자 | 사업 단위 등록 |
| Google (Gmail/Drive/Calendar) | OAuth 별도 | 대부분 | `gog` CLI 경유 |
| **Figma** | **없음** | — | **신규 개발 필요** |

→ 도구는 깔려 있으나 **누가 무엇을 실제로 쓰는지에 대한 데이터가 시스템에 없다.**

### 2.5 담당 사업·서비스 정보가 없다

`business-report`에 사업이 등록돼 있으나 이는 **SR 연동용**이다.
**개인이 어떤 사업·서비스를 담당하는지**는 어디에도 기록되어 있지 않다.

## 3. 요구사항

1. 구성원마다 **사용하는 툴이 다르다** (두레이 / 구글 드라이브 / Gmail / GitHub / SR / Figma / 구글 캘린더). 안 쓰는 건 전혀 안 씀
2. 본인이 담당한 **사업 및 서비스별로** 에이전트를 통해 보고를 받을 수 있어야 함
3. **cron으로 정기 수신** 가능해야 함
4. **금요일 메일 주간보고**에 활용 가능해야 하고, 메일 송부까지 연결되어야 함
5. **비서는 서브에이전트 관리자**다. 사용자의 모든 소통은 비서를 거치며, 서브에이전트 호출에 혼선이 없어야 함

## 4-1. 추가 확정 (2026-08-06)

| # | 결정 | 근거 |

| 7 | 기본값 수정은 **설정 화면에서만**. 카드·대화 조정은 **해당 실행 1회** 한정 | 영구/일시가 섞이면 다음 cron 결과가 예측 불가 |
| 8 | 카드에 **「이 구성을 기본값으로 저장」** 체크박스 제공 | 반복 조정을 한 번에 승격 |
| 9 | 미연동 툴은 목록에서 **비활성 처리** | 아래 5.4 "조용한 실패" 참고 |
| 10 | **사용 툴 = 사람 단위 공통 1벌** (사업별 아님) | 사업마다 두면 설정이 사업 수만큼 늘어남 |
| 11 | **보고 주기 = 사람당 1개** (사업별 아님) | 사업 3개면 보고를 3번 받게 됨 |
| 12 | **담당 사업 = 보고 항목 분류 키**로만 사용 | 항목 앞에 `[사업명]` 접두어로 묶음 |

### 설정 단위 정리

| 항목 | 단위 | 이유 |
|---|---|---|
| 사용 툴 | **사람당 1벌** | 주간보고는 사람이 쓰는 것 · 사업별 분리 시 관리 폭증 |
| 보고 주기 | **사람당 1개** | 주 1회 보고 · 사업 수만큼 발송되면 안 됨 |
| 담당 사업 | 목록 (N개) | 보고 내용을 `[사업명]`으로 분류 · SR 연동 매칭 |

- **cron(정기)** — 담당 사업 **전체를 한 건**으로 묶어 초안 생성
- **대화 요청** — 전체 또는 특정 사업만 선택 가능 (요구사항 2)
- SR 미연동 서비스(내부 과제 등)도 **이름만 등록**해 분류에 사용 가능

### 툴 지정 방식 — 검토 근거

**(1) cron과 "매번 선택"은 양립 불가**
목요일 15시 자동 실행 시 버튼을 누를 사람이 없다. 고정 설정은 필수.

**(2) 현재는 프롬프트에 하드코딩되어 있다**

| 사용자 | cron | 참조 도구 | 프롬프트 길이 |
|---|---|---|---|
| user13 | 목·금 15시 | `gog calendar list 3`, `gog mail search newer_than:7d`, `web_search` | **1,400자+** |
| user05 | 목 17시 | `gog calendar list` | 458자 |
| user05 | 수 18시 | `gog calendar list` | 402자 |
| user05 | 금 10시 | `gog calendar today`, `gog mail search` | 305자 |

사용자명·이메일까지 하드코딩(`김다영`, `da0ab@tideflo.com`). 사람이 늘거나 도구가 바뀌면 cron을 전부 찾아 수정해야 한다.

**(3) 미연동 툴 호출은 "조용한 실패"가 된다** ⚠

Dooray 미연동 사용자(user02)에게 `gog dooray projects` 실행 시 **에러가 아니라 사용법 안내문**이 반환된다.

```
사용법:
  문서 내용 검색(RAG): gog rag search 검색어
  ...
```

LLM은 이를 "결과 없음"으로 해석해 해당 항목을 **조용히 누락**시킨다. 보고서에 아무 표시도 남지 않는다.
→ 연동 상태와 무관하게 도구를 호출하게 두면 안 된다. **미연동 툴은 선택 자체가 불가능해야 한다.**

**(4) 기대 효과 — cron 지시문 단순화**

```
현재 : "gog calendar list 3로 확인하고, gog mail search newer_than:7d로…"  (1,400자)
개편 : "이번 주 업무보고 초안을 작성하라"                                   (설정된 툴을 에이전트가 참조)
```

도구 추가(Figma)나 인원 증가 시에도 **cron 수정 불필요**. 설정만 변경하면 된다.

### 설정 데이터 — 쓰기 경로

| 경로 | 위치 | 적용 범위 |
|---|---|---|
| 등록·수정 | 설정 화면 (외부 연동 › 담당 업무) | **영구** — 다음 cron부터 |
| UI 조정 | 보고 카드 체크박스 | **이번 1회** |
| 대화 조정 | "이번엔 두레이 빼고" | **이번 1회** |
| 기본값 승격 | 카드의 「기본값으로 저장」 | **영구** |

세 경로가 같은 설정을 바라보되, **쓰기는 설정 화면과 명시적 저장에만** 허용한다.

## 4-3. 역할별 업무 구분 (2026-08-06 확정)

한 사업에 기획자·개발자·디자이너가 함께 참여하고, 같은 역할끼리도 담당 업무가 다르다.
**"내가 한 일"만 골라낼 수 있는지** 툴별로 실측했다.

| 툴 | 본인 필터 | 근거 |
|---|---|---|
| 두레이 | ✅ 가능 | `dooray tasks {프로젝트ID} {size} {status} {memberIds}` — **담당자 ID 파라미터 지원** |
| Gmail | ✅ 자동 | 본인 계정 조회 |
| 구글 캘린더 | ✅ 자동 | 본인 캘린더 |
| 구글 드라이브 | ✅ 자동 | 본인이 수정한 파일 |
| GitHub | ✅ 가능 | 본인 커밋·PR |
| **SR 시스템** | ❌ **불가** | 목록 컬럼이 `sr_no · title · **requester** · status · priority · created_at · updated_at · closed_at · channel` — **처리 담당자 컬럼 없음**. `requester`는 요청자(발주처)지 처리자가 아님 |

**결론: 개인 업무보고에서 SR 제외** (2026-08-06 확정)

- SR은 **사업 단위 조회만** 가능해서, 넣으면 같은 사업의 **다른 사람이 처리한 건까지 섞인다**
- SR 기반 보고는 **`사업 주간보고` 🏢 전용**으로 유지
- 개인 업무보고는 **두레이 · Gmail · 캘린더 · 드라이브 · GitHub · Figma** 로 구성

역할 구분은 위 툴들의 본인 필터로 **자연히 해결된다** — 개발자는 GitHub·두레이 task, 기획자는 드라이브·메일·회의 중심으로 각자 다른 데이터가 잡힌다.

## 5. 미결정 — 결정 필요

### 5.1 에이전트 이름 — ✅ 확정: A안 (`업무보고` 📝)

`business-report`(사업 주간보고)와 **공통 단어를 남기면 혼동이 재발**한다.
LLM이 헷갈릴 여지를 문구가 아니라 **이름 자체로** 없애는 것이 확실하다.

| 안 | 개인 | 사업 | 평가 |
|---|---|---|---|
| A | **업무보고** 📝 | 사업 주간보고 🏢 | "주간보고" 단어가 한쪽에만 → 혼동 최소. **추천** |
| B | 주간 업무보고 | 사업 주간보고 | "주간보고" 공유 → 혼동 잔존 |
| C | **업무일지** 📝 | 사업보고서 🏢 | 양쪽 다 변경 · 가장 명확하나 기존 명칭 교체 비용 |

→ **A안 권장.** 개인 쪽만 바꾸면 되고, 사용자가 "주간보고"라 말하면 사업 쪽으로 확정 해석 가능.

### 5.2 진입 방식 — 자연어 vs UI 선택

| 방식 | 장점 | 단점 |
|---|---|---|
| 자연어만 | 별도 UI 불필요 | LLM 해석에 의존 → 혼선 위험 상존 |
| **UI 버튼 선택** | 에이전트·도구를 **명시적으로 지정** → 혼선 원천 차단 | 화면 개발 필요 |

→ 요구사항 5(혼선 금지)를 지키려면 **UI 버튼 방식이 구조적으로 안전**하다.
사업 주간보고에서 이미 QuickActions 칩 + biz-picker 카드로 검증된 패턴.
